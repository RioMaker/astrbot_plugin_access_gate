# AstrBot 独立白名单门禁

## 全局积分模式与消耗分析（2.4.0）

在 **AstrBot → 插件 → 门禁 →「积分与模型额度」→ 计费设置** 将“积分模式”切换为 **全局积分模式**，设置全局每日、每月额度后保存，后续请求立即使用新规则。需保持插件配置中的总积分开关 `credits_enabled` 启用。新模式默认关闭，已有个人积分配置不变；日额度沿用已有值（新安装默认 **10 元**），月额度默认 **300 元**，两者均可修改，**0 表示暂停服务**。

- 全局模式下所有群及门禁覆盖的私聊共享日/月预算，个人余额和单群额度不再拦截。不扣个人积分，回复也不追加积分消耗提示；原有余额保留。RP 指令仍可正常签到，但不发积分、不附带积分奖励回执。戳一戳奖励仍按原开关和规则执行。
- 日、月任一可用额度不足，暂停新门禁唤醒会话及提及判断的 LLM 请求；独立插件指令、工具内部和后台 LLM 调用继续按原边界放行。主 AI 在受控会话中选择工具及接收工具结果后的续答仍属于该会话。额度控制不改变原有白名单、开放时段和命令路由。
- 日周期按北京时间每日 00:00 切换，月周期按每月 1 日 00:00 切换。切换模式、保存设置、重载或重启不会清空消费；全局模式会计入本日、本月已有的个人模式消费。切回个人模式后恢复原个人积分、全局日额度及单群日额度规则，月限额不再生效。
- 扣分方式与费率按每笔请求开始时的快照结算。模式切换前已开始的请求保持原规则；跨日/月请求归属开始日期。已结算费用与在途/未知用量预留共同占用预算，同一事务检查日/月限额，避免并发超额放行。每次预留是估算，实际结算可能超出预留，已发出的请求不会被强行中断，后续请求会被拦截。

管理页新增 **消耗速度与分布**：可选 **今日、近 7 天（含今天）、本月**，查看按小时的人民币消耗速度、最近 60 分钟速度、已结算金额、Token 和待结算笔数。移动鼠标或拖动滑块查看小时明细；页面可见时每 60 秒刷新额度总览与分析，不覆盖尚未保存的设置。

高低峰按所选范围内同一钟点的费用除以已过去的小时数比较，显示最高和最低的时段；当前小时尚未结束，速率可能波动，未经过的时段不作为低峰，无足够差异时不生成结论。它反映账本的使用分布，与服务商模型价目表中的高峰/空闲档位不同。没有记录仅表示账本没有消费记录，未知用量不当作零消费。所有费用仍按原请求费率快照计算，含已有历史记录，不是服务商最终账单。

同页显示所选范围的群排行和用户排行（各前 20，按已结算金额排序、附金额占比和请求数），群名称获取失败时保留群号，私聊单独列出。用户列表新增累计已结算消费，总览保留各群消费、全局日/月消费和历史总消费；流水继续保留用户、群、用量、费用与模式快照。全局模式无积分扣除，但金额统计照常。

升级无需清空数据库：旧设置自动补齐新字段，旧账本、历史余额和奖励记录保留。初次安装/升级到 2.4.0 后重载插件并刷新管理页；真实 AstrBot / QQ 行为需部署后联调。

## 戳一戳奖励与原有图片回复兼容（2.3.1）

修复开启积分奖励后，原有戳一戳图片回复失效的问题：奖励处理不再终止事件传播，并保留其他插件可能使用的唤醒标记。原有戳一戳插件可继续按自身规则回复；中奖时，本插件额外发送配置的积分奖励文字或举牌图。未中奖、冷却中、重复通知和奖励处理异常也不会因为奖励功能而拦住后续插件。

同一事件经过门禁的两个监听入口时只处理一次奖励，继续抑制默认 AI 聊天。原有白名单和群聊开放时段限制仍生效。更新到 2.3.1 后重载门禁即可，无需关闭积分奖励或修改原图片插件。已完成模拟多插件顺序处理回归，真实插件组合仍需部署后验证。

## 戳一戳可可子领取积分（2.3.0）

QQ / OneBot（aiocqhttp、NapCat）用户戳本 bot 时可随机获得积分，群聊、私聊均支持。默认 **30% 中奖率、随机 1～6 分、每人滚动 8 小时最多中奖 1 次**。仅中奖消耗次数，未中奖可继续尝试；也可以改成每次有效尝试都计次。未中奖、重复通知和次数用完时，本插件不额外回复，不唤醒默认 AI 聊天；其他戳一戳插件仍可继续处理。

在 **AstrBot → 插件 → 门禁 → 配置** 修改以下选项；保存后重载插件：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `poke_reward_enabled` | `true` | 戳一戳奖励开关；关闭总积分开关时也暂停 |
| `poke_reward_probability` | `30` | 百分比，0～100；100 为必中奖 |
| `poke_reward_min` / `poke_reward_max` | `1` / `6` | 含上下限的随机整数，均可设 1～10000；相同即固定奖励 |
| `poke_reward_cooldown_hours` | `8` | 滚动限次周期，0～8760 小时，支持小数；0 表示不限次 |
| `poke_reward_max_times` | `1` | 每个周期允许触发 1～1000 次 |
| `poke_reward_count_mode` | `success` | `success` 仅中奖计次；`attempt` 每次有效尝试计次 |
| `poke_reward_reply_mode` | `image` | `text` 文字、`image` 图片、`both` 图片＋文字 |
| `poke_reward_reply` | `嘿嘿，送你一点小幸运～\n积分+{points}` | 可修改中奖文案，支持 `{points}`、`{balance}`、`{nickname}`；没写 `{points}` 时自动追加实际积分 |

内置可可子的**开心、眨眼、鼓脸**三款举牌图，中奖时随机选择。牌面由本地程序写入实际的“积分+数值”，修改奖励范围无需重新生成图片；运行时不调用图片模型或聊天模型。图片发送/渲染失败时改发自定义文字。资源、字体许可及生成提示词见 [assets/poke/README.md](assets/poke/README.md)。

奖励直接计入现有积分余额，可通过 `/积分` 查询；管理页“历史获得与消耗”可筛选 **戳一戳奖励**，流水保留本次奖励和中奖规则快照。每个 QQ 用户跨群、私聊、使用同一账本的多个 bot 共享限次，其他用户分别计算。次数与入账在同一 SQLite 事务中提交，并发、重复通知、重载及进程重启均不会重复发奖。满额后的戳一戳不延长等待时间；修改周期、次数或计次方式后，按已有记录和新规则判断。

仅接受真实 OneBot `notice / notify / poke` 通知，且目标必须为当前 bot；不奖励机器人自己戳自己、别人之间的互戳、文字伪造戳一戳或不支持的平台。遵循现有白名单和群聊开放时段，独立于普通聊天唤醒开关。OneBot 没有稳定通知 ID 时，按 bot、用户、群和上游时间去重，同一秒内字段完全相同的通知只处理一次。

升级会在原 `credits.db` 中新增戳一戳记录表，已有余额、RP 奖励和历史流水保留。积分先入账再发送回复；发送失败或任务取消后，已到账奖励仍可通过 `/积分` 查询。已完成本地账本、并发、模拟事件与图片渲染验证，真实 QQ 戳一戳收发需要部署后联调。

## Flash 0731 模型价格兼容（2.2.3）

修复部分群聊使用 `deepseek-v4-flash-0731` 时提示“尚未配置价格，无法核算成本”的问题。该完整模型名现在作为兼容别名复用当前配置的 `deepseek-flash` 峰谷价目表；如果已经为 `deepseek-v4-flash-0731` 单独配置了价格，则优先使用其专属价格。流水保留原始模型名和实际采用的价目表名称，便于核对。

这是本插件对该版本名的计费兼容规则。DeepSeek 官方当前推荐的调用名称为 [`deepseek-flash`](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)；中转平台如果对 `deepseek-v4-flash-0731` 另行定价，应在积分管理页按完整模型名填写实际价格。其他未知名称仍须单独配置。更新到 2.2.3 后重载插件生效，已有价格配置、积分和历史流水保留。

## 管理页显示群名称（2.2.2）

积分管理页的“各群额度”和“历史流水”同时显示**群名称与群号**，无需手动填写名称。通过已连接的 QQ / OneBot（aiocqhttp）机器人批量读取群列表，支持多个机器人；只配置了额度、尚无消费记录的群也会匹配名称。

群名称仅用于管理页展示，不修改账本、计费归属或历史快照。名称在访问页面时获取并缓存 60 秒；群改名后，缓存到期再次刷新即可更新。机器人离线或读取超时时继续显示本次插件运行期间缓存的名称；没有名称或不支持的平台显示“群名称暂不可用”和原群号。升级后重载插件并刷新管理页生效。

## 消耗提示补漏与不足提醒冷却（2.2.1）

修复普通文字在发送前被装饰插件重新整理时丢失扣分提示的问题：现在在所有内容整理完成后、实际发送前附加 `[积分-0.21]`，成功发送后才标记已提示。AI 直接发送文字等绕过普通结果的路径，在本轮结束后补发一次独立的 `[积分-0.21]`，不会重发正文。静默判断、已停止的消息、没有实际扣分的调用不补发。

新增 AstrBot 插件配置 **“被 @ 时积分不足提醒间隔（秒）”**（`credits_insufficient_notice_interval`），默认 **300 秒 / 5 分钟**。同一平台、机器人、群聊、发送者在固定时间窗内最多提醒一次；后续被 @ 仍拦截 LLM，只是不再回复，避免与其他 bot 连续互相触发。不同群和用户分别计时，连续 @ 不会延长时间窗；可设 0～86400 秒，0 表示每次提醒，重载后重新计时。该冷却不改变普通称呼唤醒及其他额度错误的提示。

## 回复末尾的积分消耗（2.2.0）

门禁触发的 AI 会话在最终回复末尾附上本轮实际扣分，例如 `[积分-0.21]`。同一条用户消息的提及判断、主模型和工具循环续答中已结算的扣分合并显示一次；六爻等插件的独立调用仍不扣分、不附加提示。

普通回复直接追加在正文后，流式回复在完成时追加最后一个文本片段。提示不写入模型回复或对话历史；余额查询仍只返回余额。显示通常四舍五入到两位小数，极小扣分保留原精度以免显示为零，账本精度不变。未产生实际扣分、仅预留额度或用量未知的请求不会被当作已扣积分显示。

## 积分查询回复（2.1.1）

`/积分` 与 RP 插件 0.7.3 起提供的 `/rp 积分` 共用余额查询，成功时仅回复 `当前积分：数值`，例如 `当前积分：20`。金额换算、签到奖励和计费说明保留在管理页及帮助文档中，不再附在余额回复后。

## 仅控制门禁触发的会话（2.1.0）

积分、全局每日额度和群每日额度只控制本插件通过称呼、@ 唤醒触发的普通 AI 会话，以及本插件的提及判断。六爻、五行数字等插件独立调用 LLM 一律放行，不扣积分、不占额度、不新增消费流水；WebChat、其他唤醒入口、关闭本插件唤醒后的核心会话及后台请求也不纳入此网关。原有白名单和开放时段规则仍然生效。

同时修复 AstrBot 用 `functools.partial` 绑定插件处理函数后，六爻等请求被误认成聊天的问题；识别时解析绑定和装饰器包装，覆盖指令、本地工具和事件钩子。主 AI 在受控会话中选择工具、接收工具结果后继续回复的请求仍计费，工具自身的独立调用放行。

升级并重载门禁后生效，无需修改六爻等插件。管理页保留插件自动检测，统一显示“独立调用放行”；旧版 `charged_plugins` 配置不再生效。已有积分和历史账目不重算，升级前已发生的消费和在途预留仍保留在原日期账目中。网关接入异常仅暂停门禁自身的会话入口，不再拦截其他插件或 Provider 加载。

## RP 积分和 LLM 额度（2.0.0）

在 AstrBot 插件详情的**可视化视图 / Pages → credits** 打开积分管理页。现有白名单、唤醒和开放时段规则继续生效；配置项 `credits_enabled` 控制整套积分与金额额度系统。费用参数在管理页保存至独立数据库，不写入其他插件。

### 默认奖励与兑换

- **20 积分＝¥1**；积分保留小数。当天 RP 签到奖励为 **19＋0.02×RP 分**，RP 0～100 对应 19～21 分，即 ¥0.95～¥1.05，平均约 ¥1，RP 带来的总波动为 10%。
- 按 98,000 未缓存输入＋2,000 输出的 100k token 对话示例，低谷 ¥0.106 / **2.12 分**，高峰 ¥0.212 / **4.24 分**。100k 总 token 本身不能确定价格：缓存比例、输出比例、模型和时段都会改变成本；缓存命中较多时扣分可以低于 2 分。
- 奖励基础值、每 RP 奖励、每元积分、模型单价和额度均可配置，管理页同时显示积分、人民币及三类 token 的对应关系。更改换算比例不会重算历史流水，也不会自动重估账户积分；余额按新比例显示等值金额。
- `/积分` 可查询本人余额。初始余额为 0，通过 `/rp` 领取；管理员可按原因补发或扣减积分，操作写入审计。

### 与 RP 插件的关联方案

自动发现 `astrbot_plugin_taiko_rp`（兼容旧名 `taiko_rp`）实例，适配其 `_get_today_rp_record(event)`，在真实记录成功生成/读取后发积分。`/rp` 与 RP 插件的等价 AI 工具 `get_today_rp` 都可领取；历史、排行榜及测试抽签不会发积分。

不修改 RP 插件文件、不解析图片、不另抽 RP。账本通过 **RP 来源＋用户 ID＋北京日期** 的数据库唯一约束保证一次奖励，跨群/私聊、并发请求和重启均不重复。QQ 适配器共用同一个 QQ 账户余额；其他平台按平台类型隔离，但同一个 RP 凭证仅能发给首次领取账户，与当前 RP 插件按裸用户 ID 保存记录的行为一致。当天已抽过 RP 的用户，升级后再次 `/rp` 可补领一次。

RP 插件重载后会在后续消息自动重新关联，卸载门禁恢复原方法。该接口属于 RP 插件内部方法，变更后需要更新适配器；管理页显示关联状态及错误。RP 未安装时不能签到，管理员仍可调整积分。RP 返回成功但入账失败时不会破坏抽签结果，再次获取可重试入账。

门禁 2.0.1 配合 RP 0.7.1 起，会把本次真实入账收据传给 RP 图片：首次显示“签到积分 +20”和余额，重复获取显示“今日积分已领取”和查询时余额，入账失败显示重试提示。收据仅用于本次图片/降级文字，不写入 RP 历史数据库；关闭积分或未安装关联插件时不显示该区域。

### 三级检查和实际扣分

1. 全局每日预算：默认 **¥10 / 北京自然日**，所有受控 LLM 调用共同消耗。
2. 群每日预算：默认 **¥2 / 群 / 北京自然日**，可以设置指定群覆盖值。例如 `{"123456": 5, "qq:789012": 8}`；带平台标识的规则优先，私聊仅受全局预算和个人积分约束。额度 0 表示禁止该范围调用。
3. 个人积分：门禁触发的 AI 对话要求余额 **大于 0**。一轮请求结束后按实际已报告 token 和开始时的价格快照扣分，允许本轮将余额扣成负数；下次须补到正数。为防止并发透支，同一账户只能同时有一个尚未结算的付费 Provider 请求。

**以上三级控制仅适用于门禁触发的会话和提及判断。** 其他插件独立请求不受积分或金额预算限制，也不纳入这套账本。管理员通过门禁称呼/@ 唤醒发起会话时仍适用三级控制；WebChat 使用原有入口，直接放行。

预算按请求开始的北京日期归账；跨零点完成的请求仍算开始日。余额不会每天清零，未用积分可以累计，只有每日预算自然换日。

北京时间周一至周五 09:00–12:00、14:00–18:00 为高峰，中国法定节假日除外；其他时段及周末为低谷。内置 2026 年国务院公布的放假区间，管理页可维护后续年份；未维护年份会给出日历提示。补班周末仍按 DeepSeek 的周末低谷规则处理。请求跨峰谷时按**请求开始时间**选价，供应商最终账单与退款仍以供应商记录为准。

默认支持 `deepseek-flash`、官方旧别名 `deepseek-v4-flash` / `deepseek-v4-flash-vision-exp`，以及本插件兼容的版本名 `deepseek-v4-flash-0731`；完整模型名的专属价格优先于别名映射。其他模型必须先在管理页增加其模型名称及峰谷价目表，未知模型拒绝调用，避免误套 Flash 价格。中转平台或其他币种需要填写实际人民币价格，不会自动转换汇率。模型价目表当前共用上述峰谷日历；固定价模型可把两档设成相同价格。

流水记录用户、群、来源插件、输入/缓存/输出 token、模型、Provider、价格档位与单价、兑换比例、实际扣分、结算后余额等，不保存聊天正文、提示词或 API 密钥。成本是根据供应商返回用量与配置价格计算的金额，**不是直接拉取供应商结算账单或账户余额**。原始 DeepSeek 缓存字段优先于框架规范字段；推理 token 已包含在输出中，不重复累加。流式响应只结算最后完整用量，不累加每个分片。

### 预留、异常与控制范围

- 每次调用先原子预留默认 **¥0.212**，只有全局和群剩余额度足够预留时才发起请求，结束后释放预留并结算。预留额可修改。实际请求大小无法在响应前准确获知，**在途请求可能让实际支出超过预算**；超出后停止后续请求。这是带并发预留的预算控制，不是供应商端的绝对费用上限。
- 超时、断流、取消或成功响应缺少可靠 usage 时，保留为“用量未知”，预留不会自动当作实际支出或归零。付费账户暂不能发起下一请求；管理员核对供应商后，可填写三类 token 补记，或确认未收费并释放预留。所有人工操作需填写原因。
- 进程崩溃后的在途记录恢复成待核对。插件热重载时同进程仍活跃的请求继续正常结算，不提前暴露为人工可撤销。
- 在 AstrBot 管理的 `text_chat` / `text_chat_stream` 入口仅处理门禁明确标记的会话，覆盖其普通回复和多轮工具循环；命令、工具及事件钩子的独立调用直接放行。Provider 热加载继续跟踪；内部接口不兼容时管理页报告错误，只暂停门禁会话。
- **独立插件的 Provider、HTTP/SDK、图片、语音、Embedding 等调用均不属于本账本。** DeepSeek Search/Fetch 独立 API 按次收费，当前也不包含在 token 成本中。
- 后台请求直接放行；已完成消息遗留给后台任务的上下文不会继续扣该用户积分。`billing_scope` 只描述执行归属，不会把其他调用自动纳入控制；门禁仅在自身唤醒或提及判断前明确标记会话。

### 管理、安全与升级

管理接口使用 AstrBot Dashboard Bridge 的登录身份，拒绝无登录身份的请求；框架提供 API key 用户前缀时也拒绝 API key 访问。页面提供分页/筛选、调用详情、模型与比例编辑、群覆盖、已安装插件检测、余额调整和待核对结算。并发保存设置通过版本号检测冲突；余额调整请求具有幂等编号。

持久化文件在 `data/plugin_data/astrbot_plugin_access_gate/credits.db`，SQLite WAL 与事务保护发奖/扣分。备份请使用 SQLite 在线备份，或停止 AstrBot 后连同尚未合并的 `credits.db-wal`/`credits.db-shm` 一起保存，不能运行中仅复制主数据库。配置和流水持久保存，不自动删历史。禁用/卸载门禁会停止控制，重新启用继续读取原账本。

本次仅进行了本地逻辑、并发、鉴权和模拟页面验证；真实 AstrBot/QQ、实际 DeepSeek 扣费及生产插件组合仍需部署后联调。运行边界参考本工作区 Usage Stats/Wallet Balance 的可撤销包装设计，未依赖它们的数据或要求同时安装。

## 群聊开放时段（1.4.0）

在 AstrBot 插件配置中开启“启用群聊开放时段限制”，在“群聊开放规则”里填写群聊号。
每条规则可独立设置群号、开放星期、开放开始/结束时间和休息时被 @ 的回复内容。
**星期与时间取交集：当前北京时间必须同时满足同一条规则的星期和时间，才允许普通聊天与唤醒；其他时间休息。**

例如仅选星期一、星期三，开放时间 `08:00–16:00`：

| 当前时间 | 是否开放 |
| --- | --- |
| 星期一 10:00 | 开放，星期和时间均满足 |
| 星期一 20:00 | 休息，时间不满足 |
| 星期二 10:00 | 休息，星期不满足 |
| 星期二 20:00 | 休息，星期和时间均不满足 |

- 默认每天 **08:00–16:00（北京时间，UTC+8）** 开放，不受服务器时区影响；08:00 起开放，16:00 起休息。群号留空时不生效，也支持完整的 `unified_msg_origin`。开放规则不会自动放行白名单，群聊必须先通过现有门禁。
- **开放星期支持任意选择 1～7 个星期**，默认全选；旧配置没有 `weekdays` 字段时按全部七天判断。必须至少选择一天；空列表、非列表或含非法星期值的规则会被忽略并记录错误日志，重复星期自动去重。
- 时间格式为 `HH:MM`，起止相同、时间无效或回复为空的规则会被忽略并记录错误日志。
- 跨午夜也严格按**当前星期**判断。例如仅选星期五、`22:00–06:00`，开放星期五的 `00:00–06:00` 和 `22:00–24:00`，星期六凌晨不开放。需要星期六凌晨也开放时，须将该日纳入开放规则；可使用多条规则分别安排不同日期和时段。
- 同一群可以添加多条规则，**命中任意一条完整的开放窗口即可使用**；不能将不同规则的星期和时间拼接。所有窗口均未命中时休息，提示内容取该群第一条有效规则。
- 休息期间暂停该群的普通消息、称呼唤醒、提及判断和默认 Agent；只有直接 @ 机器人时发送休息提示，不调用模型。只 @ 不说话、@ 加图片也仅发送休息提示。
- **指令仍不受时段限制**：`/rtlink`、`/help` 等照常交给指令插件，@ 加指令也不会收到休息提示。兼容核心已剥离的前缀和核心已匹配的无斜杠指令。指令仍须通过原有白名单；指令插件明确发起的 LLM 请求可继续执行，未知指令不会回落到默认聊天。
- @ 他人、@ 全体、引用或转发内部的 @ 不触发提示。管理员普通聊天同样受时段限制；管理员 `/accessgate` 管理指令始终可用。
- 私聊、WebChat 和没有有效开放规则的群不受时段限制；关闭插件唤醒或 @ 唤醒也不关闭休息提示。
- 保存配置并重载插件后生效；`/accessgate status` 显示开放时段限制开关和有效规则数量。

**升级说明：** 保留 `group_rest_enabled`、`group_rest_rules` 及其子字段名，以便读取已有配置。1.4.0 起，已有的星期和起止时间统一解释为**开放窗口**：原来填写 `08:00–16:00` 表示休息，现在表示仅在该时间开放。已有群号、星期、时间和自定义回复文本不会被自动改写，请按新含义核对配置。跨午夜不再按前一天的开始日延续到未选中的星期。

默认回复模板为：

```text
休息ing，工作时间：{work_start}-{work_end}
```

默认时段外发送 `休息ing，工作时间：08:00-16:00`。也可以将模板改为 `休息ing，开放时间：{work_days} {work_start}-{work_end}`，显示所选星期。
回复内容可以自由修改，支持以下可选占位符；其他花括号文字原样保留：

| 占位符 | 含义 | 默认时段下的值 |
| --- | --- | --- |
| `{work_days}` | 本条规则的开放星期，按周一至周日排序 | `每天` |
| `{work_start}` | 本条规则的开放开始时间 | `08:00` |
| `{work_end}` | 本条规则的开放结束时间 | `16:00` |
| `{rest_start}` | 旧模板兼容字段，等于开放结束时间 | `16:00` |
| `{rest_end}` | 旧模板兼容字段，等于开放开始时间 | `08:00` |

时间占位符均为所选规则的配置时钟值，不表示下一次开放日期，也不描述该群全部开放窗口；跨午夜规则仍须同时满足当前星期。`{work_days}` 对部分星期显示如 `星期一、星期三`。同一群设置多条规则时，建议自行填写完整的星期和开放时间说明。
本功能拦截的是经过本插件门禁的群消息；已启动的请求、定时发送、主动推送和更高优先级处理器不由此规则取消。

配置结构使用 [AstrBot 官方模板列表](https://docs.astrbot.app/dev/star/guides/plugin-config.html)，无需手动修改 JSON。

## 插件唤醒（1.1.0）

部署后将 AstrBot 系统唤醒词改为仅 `/`，清空 LLM 聊天额外唤醒前缀（删除原来的“子”），开启“私聊需要唤醒前缀”。LLM 总开关保持开启。先加载插件，再调整这些设置。

- `可可子，帮我看看`：清理称呼、空白和逗号/冒号，将 `帮我看看` 交给正常 Agent。
- `这事可可子知道吗`：使用当前会话模型先判断；明确需要回复才交给正常 Agent，保留完整正文。
- 普通提及可以沉默；判断不使用工具、不写入对话历史，超时或无效 JSON 也保持沉默。判断本身消耗一次模型请求。
- `/` 开头优先交给原有指令，不回落到默认闲聊；指令插件主动调用 LLM 的能力保留。
- @ 机器人并附带文字、图片或实际引用内容时正常唤醒。引用或转发内容中的名字不触发判断，图片和引用附件保留给正常 Agent。
- **只有 @、没有附带信息时不调用 LLM**，默认固定回复“我在，请继续说。”；休息期间改为休息提示。空白和零宽控制字符不算信息，只有引用 ID、没有引用正文或附件的标记也不算信息。关闭插件唤醒或 @ 唤醒时，空 @ 保持沉默且仍禁止原生 LLM 回落。
- 群聊/私聊白名单优先；唤醒词不能绕过权限。WebChat 沿用原生聊天。
- 只发送称呼时固定回复“我在，请继续说。”，不调用 LLM。

WebUI 可配置唤醒开关、称呼列表、提及判断、@ 唤醒；`/accessgate status` 显示插件唤醒设置。关闭插件唤醒时恢复 AstrBot 原生行为，但无附带信息的空 @ 仍由门禁阻止调用 LLM。

本功能控制普通消息进入默认 Agent 的路径；独立主动回复插件、定时任务和进行中的 Agent 追加消息需单独验证。严格按称呼唤醒时请关闭其他自动聊天/主动回复功能。不要将“无唤醒词”处理为停止全部插件，否则会影响其他插件的被动监听。

这个插件用于替代 AstrBot 核心的统一 ID 白名单，将群聊和私聊拆成两套互不影响的白名单，并默认让私聊 /rtlink 指令绕过私聊白名单。

## 必须先做的设置

在 AstrBot WebUI 中关闭核心的 ID 白名单开关 enable_id_white_list，然后重载或重启 AstrBot。

如果核心白名单仍开启，消息会在进入插件处理器之前被 AstrBot 拦截，本插件无法让 /rtlink 绕过它。

## 默认行为

- 群聊白名单和私聊白名单都默认开启。
- 空的群聊白名单会拒绝所有普通群聊。
- 空的私聊白名单会拒绝所有普通私聊。
- AstrBot 管理员默认可以绕过群聊白名单，但不能绕过私聊白名单。
- 管理员始终可以使用 /accessgate 管理指令，避免配置错误后无法恢复。
- 私聊 /rtlink、/rtlink bind、/rtlink score 等同一根指令下的用法默认放行。
- /rtlinkevil 不会被误判为 /rtlink。
- 被拒绝的消息不回复，并阻止后续插件和 LLM 继续处理。
- 对“有发送者 ID、没有群号”的适配器事件按私聊处理，避免临时会话或 OTHER_MESSAGE 绕过门禁。
- WebChat 默认放行，便于在 WebUI 中调试。

## 配置方法

1. 在 AstrBot 插件管理中加载 astrbot_plugin_access_gate。
2. 打开插件配置。
3. 在“群聊白名单”中逐行填写允许的群号。
4. 在“私聊白名单”中逐行填写允许的用户 ID；QQ 场景直接填写 QQ 号。
5. 保留“私聊白名单豁免指令”中的 rtlink，即可让所有用户私聊使用 /rtlink。
6. 发送 /accessgate status，确认“私聊管理员绕过=关”。

如果从 1.0.0 更新，AstrBot 已保存的 private_admin_bypass 可能仍为 true。Schema 默认值不会覆盖现有配置，请在 WebUI 中手动关闭“管理员绕过私聊白名单”，然后重载插件。

## 管理员批量导入

管理员可以直接发送以下指令，将内容合并进现有名单并自动去重：

    /accessgate import group <JSON、逐行或逗号分隔的群号>
    /accessgate import private <JSON、逐行或逗号分隔的用户 ID>

也支持中文写法：

    /accessgate 导入 群聊 <内容>
    /accessgate 导入 私聊 <内容>

可以直接粘贴完整 JSON、JSON 数组，或类似下面这种单个字段片段：

    /accessgate import group "id_whitelist": ["123456789", "987654321"],

该管理指令会优先于门禁执行，但只有 AstrBot 管理员能够导入；非管理员调用时不会收到回复。发送 /accessgate help 可查看用法。

发送 /accessgate status 可以检查群聊/私聊白名单开关、名单数量、管理员绕过状态、私聊豁免指令、WebChat 绕过状态及群聊开放时段限制开关和有效规则数量。

白名单也接受完整的 unified_msg_origin。如果数字 ID 与适配器实际标识不一致，可以从 AstrBot 日志中的门禁拦截记录复制 umo 值加入名单。日志不会记录消息正文。

## 安全提醒

关闭核心白名单后，本插件就是新的访问边界。不要在核心白名单关闭期间禁用或卸载本插件，否则消息将不再受这套名单过滤。

如果需要临时开放某一类会话，请关闭对应的“启用群聊白名单”或“启用私聊白名单”，不要同时停用整个插件。
